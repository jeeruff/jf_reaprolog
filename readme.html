JF PM — браузер проектов REAPER

jf_reaprolog · руководство пользователя · стиль текста — по мотивам ASD-STE100: короткие предложения, одно действие на шаг, предупреждение до действия

1Назначение

JF PM показывает все проекты REAPER на одном экране. Скрипт читает файлы .rpp как текст. Скрипт не открывает проекты при сканировании. Все данные живут в индексе jf_pm_index.json.

2Состав

ФайлФункция
jf_pm_browser.lua Браузер проектов. Главный скрипт. Запускай его.
jf_pm_core.lua Парсер, индекс, слияние. Общий модуль.
jf_pm_report.lua Отчёт при закрытии проекта.
jf_pm_watcher.lua Фоновый контроль отчётов.
jf_pm_harvest.lua Расслоение проекта на семплы.
jf_pm_gallery.lua Экспорт HTML-галереи.

3Первый запуск

  1. Запусти jf_pm_browser.lua из Action List.
  2. Нажми кнопку настройки.
  3. Нажми + Finder и выбери папку с проектами. Повтори для каждой папки.
  4. Нажми Сохранить настройки.
  5. Нажми Rescan. Дождись строки статуса.
ПРИМЕЧАНИЕ Rescan обязателен после смены путей и после обновления скрипта. Rescan наполняет карту айтемов, размеры и превью.

Панель не скроллится. Сортировка всегда видна.

5Консоль и отмена

Консоль — внизу окна: журнал действий (новые снизу), прогресс-бары фоновых процессов и строка команд. Цвет строки: действие — серый, команда — бирюзовый, отмена — синий, удаление — красный, предупреждение — янтарный.

Rescan работает в фоне: карточки собираются порциями, интерфейс живёт на старом индексе. Прогресс — на кнопке Rescan и в консоли; повторный клик останавливает.

Каталог на тысячи карточек не тормозит: сетка рисует только видимые строки, список и мета кэшируются, индекс пишется на диск отложенно (раз в полторы секунды и при выходе).

TODO-блок

Справа от консоли. Две вкладки: свой текст (редактируется прямо в панели, автосохранение через полторы секунды) и собранное — все строки с тегом #todo из имён регионов, маркеров и заметок всех проектов. Кнопка ↻ пересобирает список, сохранить пишет немедленно.

Всё хранится в одном файле jf_pm_todo.txt рядом со скриптом: свои строки выше маркера, собранные — ниже. Файл можно править любым редактором.

6Виды

Сетка

Карточки проектов. Клик — фокус (открывается большой плеер). Раскрытие — стрелкой ▾ или Enter. Двойной клик — открыть проект (в размере S — тоже, по логотипу или волне). Cmd+клик — в выборку; работает в любом месте карточки, включая волну и логотип в размере S. Закреплённые проекты всегда сверху. Проекты без отчёта — следом.

Регионы в раскрытой карточке кликабельны. Клик — регион вставляется subproject-айтемом в активный проект у курсора. Cmd+клик — регион идёт в корзину. Хэштеги в имени региона (#ambient #flute) подсвечиваются цветом, #+++ — рейтинг.

Таймлайн

Строка на проект. Бар — от старейшего бэкапа до последнего сохранения. Горизонт — полгода.

Календарь

Тепловая карта активности. Скролл — в прошлое. Активность: сохранения, бэкапы, отчёты. Будущее показывает дедлайны: янтарная рамка — дедлайн, красная — просроченный, белая — сегодня.

Канбан

Колонка на класс. Перетащи карточку мышью в другую колонку. Или используй Shift+H/L. Кнопка ▸ на карточке открывает проект; Enter и o делают то же с карточки в фокусе.

ВНИМАНИЕ Канбан пишет статус в индекс, не в файл проекта. Файл .rpp остаётся нетронутым. Отчёт при закрытии проекта записывает статус в .rpp и отменяет статус из канбана.

8Тамбнейлы и превью

Порядок выбора картинки для карточки:

  1. Превью, назначенное вручную. Кнопка превью… в раскрытой карточке.
  2. Файл <имя проекта>.png / .jpg в папке проекта.
  3. Файл jf_thumb.png / .jpg в папке проекта.
  4. Генерируемый стиль: калейдоскоп, иероглиф или навигатор.

Навигатор рисует айтемы проекта: строка — трек, горизонталь — время. Полоса внизу — регионы. Цвет региона зависит от имени. Регион «intro» выглядит одинаково во всех проектах.

Аудио-превью (микро-плеер)

Полоска волны внизу каждой карточки. Клик — играть, клик — стоп. Вид пиков — в настройках: волна или спектр (цвет — частота).

Источник звука, по порядку: <имя проекта>_preview.wav в папке проекта, прокси сабпроекта, файл из RENDER_FILE проекта. Полоска превью видна всегда; под ней — ряд прозрачных кнопок карточки: развернуть (▾) и выбрать слева, удалить справа. Клик по карточке — только фокус; раскрытие — стрелкой или Enter. Размеры: S — микро-строка (логотип + волна; наведи на логотип — кнопка ▶/■), M — горизонтальный клип, L — обычная карточка. Если превью не отрендерено, скрипт фаззи-ищет готовый рендер в папке проекта по похожему имени. Кнопка найти превью (в строке выборки) идёт дальше: Spotlight по всему диску, по одному проекту за кадр, с прогрессом в консоли; найденное запоминается в карточке.

Карточки и есть мини-плееры. Для выбранных: ▶ все — одновременно, ▶▶ — по очереди, ■ — стоп. Размер S — горизонтальный клип, как в Ableton.

Питч, анализ, BPM-синк

В шапке большого плеера: крутилка pt — питч превью в полутонах (live, на играющее), кнопка analyze — анализ wav-превью: тональность (или две, если борются) по хроме Крумхансла и BPM по автокорреляции огибающей. Результат — в карточке и в шапке плеера; консольная команда analyze — по всей выборке.

Scale sync: кнопка M на плеере назначает клип мастером тональности, кнопка S на другом клипе подстраивает его питчем под мастера (кратчайший сдвиг корня, ±6 полутонов; тональности — из analyze или имени).

В панели плейлиста: мастер-BPM и чип sync — играющие превью подтягиваются к мастер-темпу (rate, питч сохраняется). Совмещай наработки из разных темпов в один грув.

Лупы и большой плеер

Клик по карточке фокусирует её — над сеткой появляется большой плеер. Выбери несколько карточек — их плееры встанут стеком один над другим (до четырёх), а слева появится плейлист в стиле region manager: превью и все лупы выбранных по номерам. Кнопка playlist в панели открывает его всегда — можно перетащить туда карточки мышью и собрать свой порядок, не трогая выборку. ⇉ sync запускает все элементы одновременно (с BPM-синком они лягут в один грув). Клик по строке — играть параллельно; ▶ — последовательно, чип «повтор» — по кругу; в проект — экспорт плейлиста новым проектом из сабпроектов. Воспроизведение параллельно по умолчанию: запуск чужого превью не гасит крутящийся луп — совмещай наработки на слух. Кнопка ■ в панели плейлиста — главный плеер: глушит все превью, где бы они ни играли. Точечно: правый клик по волне или ■ у конкретного плеера. Клик по волне — играть с этого места. Драг мышью — выделить луп-регион, кнопка + луп сохраняет его в карточку (живёт в индексе, переживает Rescan). Кнопка ▶N под волной играет луп по кругу, × удаляет.

Собрать из лупов (в строке выборки) строит новый проект: каждый луп выбранных проектов — сабпроджект-айтем, обрезанный по лупу, последовательно. Айтемы открываются двойным кликом — это маркеры в исходный проект, не копии аудио. Границы сэмпл-точные: рендер запоминает срез тишины в начале (pv_offset) и компенсирует его при сборке. Для превью, отрендеренных до этой версии, перерендери превью один раз. Чип снэп в плеере притягивает границы лупа к битовой сетке проекта (по BPM карточки, такты ярче); сетка видна на волне. Клик по волне — играть с места клика; клик во время игры — сик; правый клик — стоп. Громкость — слайдер vol в панели. Если звука нет — нажми ▸ в раскрытой карточке: скрипт откроет проект, отрендерит <имя>_preview.wav на полной скорости (offline) и вернёт рендер-настройки на место. У проекта нет конца — рендерится первый регион. Лимит превью — 5 минут. Громкость нормализуется в −18 LUFS, пики клипуются брикволлом. Тишина в начале режется до 0.5 c, в хвосте — до 1 c. В настройках есть кнопка «Сделать превью всем проектам»: очередь рендерит проекты без аудио по одному, её можно остановить. Готовые превью не перерендериваются; превью из сплошной тишины (битый рендер) рендерится заново. Проекты с пропавшими медиафайлами очередь пропускает — модальный диалог REAPER не повесит батч. Дата изменения проектов при этом не меняется.

Полное демо

Иконка ▶ в ряду команд рендерит весь проект целиком в <имя>_demo.wav — без лимита 5 минут, с той же нормализацией −18 LUFS и брикволлом.

Пустые проекты

Значок ∅ на карточке: у проекта нет айтемов или в его папке нет ни одного аудиофайла. Чип-фильтр «пустые» показывает только их.

Бэкапы

Список бэкапов в раскрытой карточке кликабелен. Клик по строке открывает бэкап в новой вкладке. Кнопка ↩ восстанавливает проект из этого бэкапа: текущий файл сохраняется рядом как <имя>_before-restore.rpp. Закрой проект перед восстановлением.

Даты

Чип дата — по времени файла проекта. Чип сохранён учитывает и бэкапы: проект со свежим .rpp-bak поднимается наверх, даже если сам .rpp старше.

Дата открытия

Чип сортировки открыт ставит наверх недавно открытые проекты. Источник: список недавних проектов REAPER, для остальных — время последнего чтения файла. Дата видна в раскрытой карточке.

BPM и тональности

Тег в имени проекта — [160] или 160bpm — считается темпом и важнее TEMPO из файла. Разброс темпа по огибающей показывается как 90-160 BPM. Тональности берутся из имени проекта, регионов, маркеров и треков. Чип сортировки bpm — по темпу.

Авто-категории, дубли, рейтинг тейков

У проектов без класса карточка показывает подсказку по содержимому: ~семпл (короче минуты), ~скетч (короткий, пара треков), ~джем (длиннее получаса), ~аранжировка (6+ треков и 3+ регионов), ~тест (test/тест в имени). Клик по подсказке принимает её как класс; команда autoclass — принять для всей выборки или вида.

Чип ⧉ дубли показывает подтверждённые дубли. Похожее имя — только кандидат; дальше скрипт проверяет содержимое:

ВердиктЧто значит
⧉ копия (красная) Побайтно одинаковый файл (размер + хеш головы, середины и хвоста). Удалять безопасно.
⧉v версия (янтарная) Тот же проект в развитии: структура совпадает (треки ±25%, длительность ±15%), байты — нет.
бэкапФайл из папки Backup/Backups или с меткой autosaved / .bak. / overwritten — в фильтр не попадает.
просто похожиеИмя совпало, содержимое разное — отсеивается.

Команда dups печатает группы с числом копий и версий, dups copies — полные пути побайтных копий.

Смайлик ☺ (или ★ при #+++) на карточке — в регионах есть отметки удачных тейков вида #+.

Класс проекта

Класс описывает материал проекта — что внутри, а не что ты должен. Императивов нет намеренно: «доделать» читается как невыполненный долг.

Выпадашка на каждой карточке. В канбане у каждого класса своя колонка. Последний пункт выпадашки — «удалить…»: перенос в Корзину с подтверждением. При выборке кнопка «на расслоение» ставит класс всем выбранным. Класс пишется в индекс, как в канбане. Старые статусы читаются и отображаются новыми классами: файлы проектов не переписываются.

ID трека и семплы

В раскрытой карточке: «ID трека» и «Семплы» — свободные поля, пишутся в файл проекта. Семплы ищутся в fzf.

Проекты других DAW в каталоге

Rescan находит не только .rpp: Ableton (.als), FL Studio (.flp), Renoise (.xrns), Pro Tools (.ptx .ptf), Logic (.logicx), Bitwig, Nuendo, Pure Data, Max. Добавь их папки в настройки путей.

Такие карточки помечены цветным бейджем DAW перед именем и плашкой на тамбнейле: [Ab] [FL] [Rn] [PT] [Lg]… Чип сортировки daw группирует каталог по программам. Двойной клик или ▸ открывает проект в его программе. Классы, теги, закреп, дедлайн-фильтры и канбан работают как у REAPER-проектов; рендер и правка .rpp — нет.

Аудио-превью чужого проекта: <имя>_preview.wav или экспорт <имя>.wav/.mp3 рядом с проектом. Обложка — <имя>.png. Чипы-фильтры по DAW появляются в ряду фильтров. Папка Backup Ableton пропускается — автосейвы не засоряют каталог.

Связанные DAW-проекты

Имя файла с расширением .als .ptx .lpx .rns .flp и др. в заметках или имени региона становится кнопкой в строке «DAW:». Клик открывает проект: сначала папка проекта, потом поиск Spotlight.

9Теги

Палитра тегов лежит в начале файла jf_pm_browser.lua, таблица TAGS. Правь её текстовым редактором. Формат: { 'имя', 0xRRGGBBAA }.

Назначение: раскрой карточку, кликни тег в строке «Теги». Повторный клик снимает тег. Тег не из палитры получает цвет от хеша имени.

ПРИМЕЧАНИЕ Теги из трёх источников: extstate проекта, теги Finder, браузер. Браузер снимает только свои теги. Теги проекта и Finder снимай в их источнике.

10Слияние проектов (merge)

  1. Выбери проекты по порядку: x или Cmd+клик. Номер на карточке — позиция в склейке.
  2. Нажми merge на панели или клавишу m.
  3. Найди результат: merge_ГГММДД_ЧЧММ.rpp в папке первого проекта.
  4. Открой результат и проверь его до работы.

Слияние складывает треки всех проектов в один файл. Айтемы и маркеры последующих проектов сдвигаются на суммарную длительность предыдущих. Каждый проект получает свой регион. Пути аудио становятся абсолютными.

ВНИМАНИЕ Слияние — текстовое. Исходные проекты не изменяются. Ограничения результата: точки огибающих не сдвигаются; айтемы с привязкой BEAT могут сместиться при разнице темпов; темп берётся из первого проекта; GUID-ы не перегенерируются. Не сливай проект сам с собой.

Слияние сабпроектами

Кнопки merge as subs и subs → проект… не склеивают текст. Каждый выбранный проект становится одним айтемом-сабпроектом на своём треке. Двойной клик по айтему открывает исходный проект. Скрипт сам рендерит прокси: открывает каждый саб, сохраняет, закрывает.

ПРИМЕЧАНИЕ Исходные проекты не изменяются. Прокси — это wav-рендер саба. REAPER обновляет прокси при каждом сохранении саба.

11Переименование проекта

  1. Закрой проект в REAPER, если он открыт.
  2. Раскрой карточку. Нажми иконку Aa.
  3. Введи новое имя. Нажми Enter.

Скрипт переименовывает всё с префиксом старого имени: .rpp, бэкапы в папке и в Backups/, пики .reapeaks, превью <имя>.png. Папка проекта переименовывается, если названа как проект. Относительные пути внутри .rpp остаются валидными.

ВНИМАНИЕ Скрипт проверяет все коллизии до первого переименования. Результат — либо всё, либо ничего. Абсолютные пути из других проектов на эту папку (например, после merge) не обновляются.

12Удаление проекта

Кнопка × на карточке не удаляет файлы. Проект уходит в виртуальную корзину: исчезает из каталога, но остаётся на диске. На карточке видно 🗑N — сколько дней осталось до настоящего удаления (по умолчанию 30).

  1. Чип 🗑 корзина в ряду фильтров показывает удалённое.
  2. × на карточке в корзине возвращает проект. Cmd+Z тоже возвращает.
  3. вернуть все — восстановить всю корзину разом.
  4. удалить просроченные — отправить в Корзину macOS то, что пролежало дольше срока.

Просроченное уезжает в Корзину macOS автоматически при запуске скрипта. Команды: trash — список, trash sweep — очистка, trash restore — вернуть всё.

ПРИМЕЧАНИЕ В корзину пишется только пометка в индексе — файлы не двигаются, пока не истечёт срок. По истечении удаляется только .rpp; папка проекта с аудио остаётся.
ПРЕДУПРЕЖДЕНИЕ Массовое удаление из строки выборки тоже кладёт в корзину. Настоящее удаление в Корзину macOS происходит только по истечении срока или по кнопке «удалить просроченные». Восстановление после этого — из Корзины macOS.
  1. Раскрой карточку и нажми удалить…. Или нажми Shift+D на карточке в фокусе.
  2. Ответь в диалоге: Да — папку целиком, Нет — только .rpp, Отмена — ничего.

Если папка проекта — корень сканирования, скрипт удаляет только .rpp. Это защита от удаления всей библиотеки.

13Галерея

Кнопка галерея пишет автономный HTML рядом со скриптом и открывает его. Лупы видны янтарными скобками поверх навигатора (в секундах проекта), счётчик ⟲N — в мете; проекты чужих DAW — с цветной плашкой программы. Галерея повторяет текущий вид: фильтры и сортировка сохраняются. Файл можно отправить кому угодно. Ручные превью в галерее видны только на этой машине.

15Заметки, TODO, дедлайны

Парсер читает заметки трёх уровней: project notes, заметки треков, заметки айтемов. Раскрой карточку. Открой свёрнутые ветки «Заметки…». Текст понимает md-синтаксис: # — заголовок, - — пункт списка.

TODO

Строка - [ ] текст в отчёте или в project notes становится чекбоксом в карточке. Клик по чекбоксу переключает пункт. Скрипт правит текст .rpp напрямую.

Дедлайны

  1. Раскрой карточку. Нажми назначить в строке «Дедлайн».
  2. Введи дату: дд.мм или дд.мм.гг. Нажми Enter.

Дедлайн виден на свёрнутой карточке и в календаре. Дедлайн также задаётся из отчёта при закрытии проекта.

ВНИМАНИЕ Чекбоксы и дедлайн с карточки правят файл .rpp. Открытый проект скрипт не трогает — покажет окно. Отчёт зеркалится в project notes ниже маркера --- JF PM ---. Текст выше маркера — твой, он сохраняется.

16Требования

  • REAPER 7, macOS.
  • ReaImGui 0.9+ — обязательно.
  • SWS — для плееров превью (CF_Preview) и открытия файлов.
  • js_ReaScriptAPI — для Finder-диалогов путей и mtime без запуска stat. Без него работает запасной путь.

17Состояние на сейчас

Версия 1.0. В каталоге ~2190 карточек: 228 проектов REAPER и остальное — Ableton, FL Studio, Logic, Pro Tools, Nuendo, Renoise. Автоклассы проставлены 333 проектам. Найдено 376 групп похожих имён: 177 побайтных копий, 264 версии, остальное — ложные совпадения.

Хвосты на потом

  • Прокси сабпроектов: id экшна «Open associated project in new tab» ищется автоматически, но на другой сборке REAPER стоит проверить.
  • Анализ тональности и BPM работает только по wav-превью; для mp3-рендеров нужен свой декодер.
  • Для чужих DAW содержимое не парсится — категории и пустышки считаются только по имени, размеру и дате.
  • 177 побайтных копий ждут решения: dups copies печатает их пути.
