JF PM — браузер проектов REAPER

jf_reaprolog · руководство пользователя · стиль текста — по мотивам ASD-STE100: короткие предложения, одно действие на шаг, предупреждение до действия

1Назначение

JF PM показывает все проекты REAPER на одном экране. Скрипт читает файлы .rpp как текст. Скрипт не открывает проекты при сканировании. Все данные живут в индексе jf_pm_index.json.

2Состав

ФайлФункция
jf_pm_browser.lua Браузер проектов. Главный скрипт. Запускай его.
jf_pm_core.lua Парсер, индекс, слияние. Общий модуль.
jf_pm_report.lua Отчёт при закрытии проекта.
jf_pm_watcher.lua Фоновый контроль отчётов.
jf_pm_harvest.lua Расслоение проекта на семплы.
jf_pm_gallery.lua Экспорт HTML-галереи.

3Первый запуск

  1. Запусти jf_pm_browser.lua из Action List.
  2. Нажми кнопку настройки.
  3. Нажми + Finder и выбери папку с проектами. Повтори для каждой папки.
  4. Нажми Сохранить настройки.
  5. Нажми Rescan. Дождись строки статуса.
ПРИМЕЧАНИЕ Rescan обязателен после смены путей и после обновления скрипта. Rescan наполняет карту айтемов, размеры и превью.

Панель не скроллится. Сортировка всегда видна.

6Виды

Сетка

Карточки проектов. Клик — раскрыть. Двойной клик — открыть. Cmd+клик — в выборку. Закреплённые проекты всегда сверху. Проекты без отчёта — следом.

Регионы в раскрытой карточке кликабельны. Клик — регион вставляется subproject-айтемом в активный проект у курсора. Cmd+клик — регион идёт в корзину. Хэштеги в имени региона (#ambient #flute) подсвечиваются цветом, #+++ — рейтинг.

Таймлайн

Строка на проект. Бар — от старейшего бэкапа до последнего сохранения. Горизонт — полгода.

Календарь

Тепловая карта активности. Скролл — в прошлое. Активность: сохранения, бэкапы, отчёты. Будущее показывает дедлайны: янтарная рамка — дедлайн, красная — просроченный, белая — сегодня.

Канбан

Колонка на статус. Перетащи карточку мышью в другую колонку. Или используй Shift+H/L.

ВНИМАНИЕ Канбан пишет статус в индекс, не в файл проекта. Файл .rpp остаётся нетронутым. Отчёт при закрытии проекта записывает статус в .rpp и отменяет статус из канбана.

7Тамбнейлы и превью

Порядок выбора картинки для карточки:

  1. Превью, назначенное вручную. Кнопка превью… в раскрытой карточке.
  2. Файл <имя проекта>.png / .jpg в папке проекта.
  3. Файл jf_thumb.png / .jpg в папке проекта.
  4. Генерируемый стиль: калейдоскоп, иероглиф или навигатор.

Навигатор рисует айтемы проекта: строка — трек, горизонталь — время. Полоса внизу — регионы. Цвет региона зависит от имени. Регион «intro» выглядит одинаково во всех проектах.

Аудио-превью (микро-плеер)

Полоска волны внизу каждой карточки. Клик — играть, клик — стоп. Вид пиков — в настройках: волна или спектр (цвет — частота).

Источник звука, по порядку: <имя проекта>_preview.wav в папке проекта, прокси сабпроекта, файл из RENDER_FILE проекта. Клик по волне — играть с места клика; клик во время игры — сик; правый клик — стоп. Громкость — слайдер vol в панели. Если звука нет — нажми ▸ в раскрытой карточке: скрипт откроет проект, отрендерит <имя>_preview.wav на полной скорости (offline) и вернёт рендер-настройки на место. У проекта нет конца — рендерится первый регион. Лимит превью — 5 минут. Громкость нормализуется в −18 LUFS, пики клипуются брикволлом. Тишина в начале режется до 0.5 c, в хвосте — до 1 c. В настройках есть кнопка «Сделать превью всем проектам»: очередь рендерит проекты без аудио по одному, её можно остановить. Дата изменения проектов при этом не меняется.

Класс проекта

Выпадашка на каждой карточке: идея → доделать → отмиксить → мастеринг → издано, вне пайплайна — семплпак (разобрать на семплы) и архив. В канбане у каждого класса своя колонка. Класс пишется в индекс, как в канбане. Старые статусы читаются и отображаются новыми классами.

ID трека и семплы

В раскрытой карточке: «ID трека» и «Семплы» — свободные поля, пишутся в файл проекта. Семплы ищутся в fzf.

Связанные DAW-проекты

Имя файла с расширением .als .ptx .lpx .rns .flp и др. в заметках или имени региона становится кнопкой в строке «DAW:». Клик открывает проект: сначала папка проекта, потом поиск Spotlight.

8Теги

Палитра тегов лежит в начале файла jf_pm_browser.lua, таблица TAGS. Правь её текстовым редактором. Формат: { 'имя', 0xRRGGBBAA }.

Назначение: раскрой карточку, кликни тег в строке «Теги». Повторный клик снимает тег. Тег не из палитры получает цвет от хеша имени.

ПРИМЕЧАНИЕ Теги из трёх источников: extstate проекта, теги Finder, браузер. Браузер снимает только свои теги. Теги проекта и Finder снимай в их источнике.

9Слияние проектов (merge)

  1. Выбери проекты по порядку: x или Cmd+клик. Номер на карточке — позиция в склейке.
  2. Нажми merge на панели или клавишу m.
  3. Найди результат: merge_ГГММДД_ЧЧММ.rpp в папке первого проекта.
  4. Открой результат и проверь его до работы.

Слияние складывает треки всех проектов в один файл. Айтемы и маркеры последующих проектов сдвигаются на суммарную длительность предыдущих. Каждый проект получает свой регион. Пути аудио становятся абсолютными.

ВНИМАНИЕ Слияние — текстовое. Исходные проекты не изменяются. Ограничения результата: точки огибающих не сдвигаются; айтемы с привязкой BEAT могут сместиться при разнице темпов; темп берётся из первого проекта; GUID-ы не перегенерируются. Не сливай проект сам с собой.

Слияние сабпроектами

Кнопки merge as subs и subs → проект… не склеивают текст. Каждый выбранный проект становится одним айтемом-сабпроектом на своём треке. Двойной клик по айтему открывает исходный проект. Скрипт сам рендерит прокси: открывает каждый саб, сохраняет, закрывает.

ПРИМЕЧАНИЕ Исходные проекты не изменяются. Прокси — это wav-рендер саба. REAPER обновляет прокси при каждом сохранении саба.

10Переименование проекта

  1. Закрой проект в REAPER, если он открыт.
  2. Раскрой карточку. Нажми иконку Aa.
  3. Введи новое имя. Нажми Enter.

Скрипт переименовывает всё с префиксом старого имени: .rpp, бэкапы в папке и в Backups/, пики .reapeaks, превью <имя>.png. Папка проекта переименовывается, если названа как проект. Относительные пути внутри .rpp остаются валидными.

ВНИМАНИЕ Скрипт проверяет все коллизии до первого переименования. Результат — либо всё, либо ничего. Абсолютные пути из других проектов на эту папку (например, после merge) не обновляются.

11Удаление проекта

ПРЕДУПРЕЖДЕНИЕ «Да» удаляет папку проекта целиком со всем аудио. Проверь ответ в диалоге до нажатия. Восстановление — из Корзины macOS.
  1. Раскрой карточку и нажми удалить…. Или нажми Shift+D на карточке в фокусе.
  2. Ответь в диалоге: Да — папку целиком, Нет — только .rpp, Отмена — ничего.

Если папка проекта — корень сканирования, скрипт удаляет только .rpp. Это защита от удаления всей библиотеки.

12Галерея

Кнопка галерея пишет автономный HTML рядом со скриптом и открывает его. Галерея повторяет текущий вид: фильтры и сортировка сохраняются. Файл можно отправить кому угодно. Ручные превью в галерее видны только на этой машине.

14Заметки, TODO, дедлайны

Парсер читает заметки трёх уровней: project notes, заметки треков, заметки айтемов. Раскрой карточку. Открой свёрнутые ветки «Заметки…». Текст понимает md-синтаксис: # — заголовок, - — пункт списка.

TODO

Строка - [ ] текст в отчёте или в project notes становится чекбоксом в карточке. Клик по чекбоксу переключает пункт. Скрипт правит текст .rpp напрямую.

Дедлайны

  1. Раскрой карточку. Нажми назначить в строке «Дедлайн».
  2. Введи дату: дд.мм или дд.мм.гг. Нажми Enter.

Дедлайн виден на свёрнутой карточке и в календаре. Дедлайн также задаётся из отчёта при закрытии проекта.

ВНИМАНИЕ Чекбоксы и дедлайн с карточки правят файл .rpp. Открытый проект скрипт не трогает — покажет окно. Отчёт зеркалится в project notes ниже маркера --- JF PM ---. Текст выше маркера — твой, он сохраняется.

15Требования

  • REAPER 7, macOS.
  • ReaImGui 0.9+ — обязательно.
  • js_ReaScriptAPI — для Finder-диалогов путей и mtime без запуска stat. Без него работает запасной путь.
