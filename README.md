# JF Project Manager

Обзор Reaper-проектов без открытия проектов: сетка карточек, статусы, отчёты
по манифесту (п. 5: «закрывая проект — отчёт»). Источник правды — extstate
внутри `.rpp` (namespace `JF_PM`), браузер читает только JSON-индекс.

## Состав

| Файл | Что делает |
|---|---|
| `jf_pm_core.lua` | Общий модуль: парсер `.rpp` как текста, JSON, индекс, настройки. Сам по себе не запускается |
| `jf_pm_browser.lua` | Браузер: сетка карточек, фильтры, сортировка, Rescan. Запуск по хоткею, в фоне не висит |
| `jf_pm_report.lua` | Окно отчёта «что сделано / что надо». Вешается на **Cmd+W** вместо штатного закрытия |
| `jf_pm_watcher.lua` | Фоновый toggle-луп ~1 сек: ловит проекты, закрытые мимо отчёта, помечает «без отчёта» |
| `jf_pm_harvest.lua` | Расслоение открытого проекта: мультитреки (`$track`) и/или регионы (`$region`) в заданные папки, опционально статус «архив» |
| `tests/` | Тесты парсера, гоняются без Reaper: `lua5.4 tests/test_parser.lua` |

Требуется: Reaper 7.x, ReaImGui 0.9+, js_ReaScriptAPI, SWS (для автозапуска watcher).

## Установка

1. Все четыре `.lua` — в одну папку, например `~/Library/Application Support/REAPER/Scripts/JF_PM/`
2. Action List → **New action → Load ReaScript** → выбрать browser, report, watcher, harvest (core не грузить — это модуль)
3. Хоткеи:
   - browser — любой хоткей (например Cmd+Shift+P)
   - **report — Cmd+W** (снять Cmd+W с `File: Close project` в Action List)
4. Запустить browser → кнопка «пути» → три пути: **проекты** (через `;`),
   **расслоение → мультитреки**, **расслоение → регионы** → Сохранить → **Rescan**
5. Watcher: запустить один раз (повторный запуск выключает). Автозапуск —
   SWS: Extensions → Startup actions → Set global startup action

Индекс лежит рядом со скриптами: `jf_pm_index.json`. Удалить его безопасно —
Rescan пересоберёт, но флаги «без отчёта» потеряются (они живут только в индексе).

## Почему report — не custom action из двух шагов

В handover предлагался custom action «скрипт → File: Close project».
Так не работает: defer-скрипт (ReaImGui-окно) возвращает управление сразу,
и Close выполнился бы до появления окна. Поэтому скрипт закрывает таб сам
(`40860 Close current project tab`) после записи. Кнопки:

- **Сохранить и закрыть** — extstate + индекс + save + закрытие таба
- **Сохранить** — то же без закрытия (отчёт посреди сессии)
- **Закрыть без отчёта** — трение: явный клик; проект всплывёт в браузере наверх с пометкой
- Esc / крестик — отмена, ничего не происходит

Поле «что надо сделать» подтягивает прошлый todo, история пишется в
`REPORT_LOG` и не затирается.

## Карточка: что откуда

- **Из `.rpp` текстом** (Rescan, проект не открывается): темп/размер, треки,
  регионы (= структура трека), маркеры, render-путь, длительность по item/регионам
- **Из extstate** (пишет report-скрипт): статус, описание, теги, отчёты
- **Из файловой системы**: mtime (js_ReaScriptAPI `JS_File_Stat`, фолбэк `stat`),
  теги Finder (`mdls -raw -name kMDItemUserTags`, не `xattr`)

## Статус — это решение, не полка

Пайплайн (прогресс, на карточке точками `●●○○`):
`набросок → в работе → к миксу → готово`

Решения вне пайплайна:
- **на расслоение** — трек не едет, но материал живой: разобрать на семплы.
  Это закрытие петли, не провал
- **архив** — расслоение сделано / проект закрыт, скрыт из «активных»
- **заморожено** — решение отложено сознательно (не «забыто»)

Зачем так:
- Каждый открытый проект без решения — открытая петля, которая ест рабочую
  память (эффект Зейгарник). Статус + «что надо сделать» выносят петлю из
  головы в систему — карточка показывает первую строку todo как `→ следующий шаг`
- **WIP-лимит**: в тулбаре счётчик «в работе + к миксу»; больше трёх —
  краснеет. Переключение контекста оставляет attention residue, три
  параллельных трека — практический потолок
- «На расслоение» снимает sunk cost: неудавшийся трек превращается в урожай
  семплов, а не висит укором. Решение принимается в еженедельном ревью:
  открыть браузер, фильтр «набросок», по каждому — в работу / на расслоение /
  заморозить

## Браузер

Три вида (чипы сверху): **сетка / таймлайн / календарь**. Без слайдеров и
выпадашек — фильтры, сортировка и виды переключаются чипами в один клик:
шире, не глубже.

- **Сетка**: клик — раскрыть детали (регионы, треки, отчёт, бэкапы, путь),
  **двойной клик — открыть проект в новой вкладке**; ячейка `□` в углу —
  в выборку; в деталях команды — иконками с тултипами, `+` у тегов —
  свой тег не из списка
- **Таймлайн**: строка на проект, бар от старейшего бэкапа до последнего
  сохранения, цвет — статус; ось — полгода
- **Календарь**: тепловая карта активности (сохранения + бэкапы + отчёты)
  от старейшего проекта до сегодня, скролл в прошлые месяцы, старт — на
  текущем; ховер — какие проекты трогал в этот день
- **Канбан**: карточки с тамбнейлами, перенос между статусами — drag&drop
  или `Shift+H/L`
- Выделено ≥2 — в тулбаре появляются команды на всю выборку: merge,
  открыть, закрепить, удалить
- Фильтр по умолчанию «активные» — всё, кроме архива
- «Без отчёта» всегда всплывают наверх
- Rescan — только кнопкой, автоматики нет

**Vim-навигация**: `h/j/k/l` — фокус по карточкам (в таймлайне `j/k`),
`Enter` — раскрыть/свернуть (в таймлайне — открыть проект), `o` — открыть
проект, `/` — в поле тега, `g`/`G` — в начало/конец, `Esc` — свернуть/сброс.

**Тамбнейлы**: свой файл `jf_thumb.png`/`.jpg` в папке проекта; иначе
генерируется детерминированно из пути проекта — 8-битный калейдоскоп
(зеркальный по обеим осям) или радикал иероглифа, стиль в настройках.

**Бэкапы**: в раскрытой карточке скрытая ветка «Бэкапы (N)» — `.rpp-bak`,
autosave и таймстамп-копии рядом с проектом и в `Backups/`, с датой и размером.

## Расслоение (`jf_pm_harvest.lua`)

Для открытого проекта, статус «на расслоение»:

- **Мультитреки** — все треки стемами в `<stems_path>/<проект>/` (`$track`,
  RENDER_SETTINGS=3 stems selected tracks, границы — весь проект)
- **Регионы** — мастер-микс, порезанный по регионам, в `<regions_path>/<проект>/`
  (`$region`, RENDER_BOUNDSFLAG=3 all project regions)
- Галка «после расслоения поставить статус „архив“» (по умолчанию включена)

Рендерит действием 41824 без диалога, текущие настройки рендера и выделение
треков сохраняются и возвращаются как были. Формат файлов берётся из последних
настроек рендера проекта (обычно wav — проверь перед первым прогоном).
